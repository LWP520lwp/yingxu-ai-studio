# 连续剧本工作流

本模块属于 AI 画布，每个画布草稿有独立的角色、场景、道具、分镜历史和末镜状态。不会写入科普短视频草稿或剪辑轨道。

## HTTP

所有接口使用当前登录用户的会话，按项目 owner 校验并设置 `Cache-Control: no-store`。

基础路径：`/api/projects/{projectId}/story-workflow`。

| 方法 | 路径 | 请求或响应 |
| --- | --- | --- |
| GET | 基础路径 | `{revision, document, updatedAt?}`；未保存返回 revision 0 |
| PUT | 基础路径 | `{baseRevision, document}`；返回新快照 |
| GET | `/tasks` | `{tasks: [...]}`；最近20个任务 |
| POST | `/tasks` | `{revision, operation}`；202 返回持久化任务 |
| POST | `/tasks/{taskId}/cancel` | 返回取消后或已经完成的任务 |

`operation` 为 `extract`（抽取档案）、`segment`（生成下一段）、`first`（抽档与首段一起提交）。`first` 的两个模型步骤全部通过才保存；第二步失败不会留下半份档案。

客户端可编辑字段只有 `title, world, novel, paragraph, model, characters, scenes, props`，不能提交/伪造 `segments` 或 `lastState`。`baseRevision` 必须与当前快照一致，冲突返回409 `STORY_REVISION_CONFLICT`。任务开始时固定所读快照；完成时若草稿已更新，任务失败并保留用户的新版本。

任务公开字段为 `id, operation, model, status, stage, createdAt, updatedAt, error?, resultRevision?`。响应不含凭证、模型指纹、租约和原始输入快照。每位用户最多一个 queued/running 任务；每个实例最多两个执行，全部署通过数据库调度锁限制为八个 running 任务。

## 输入、模型与连续性

- 小说/章节最多120,000字符，全剧设定12,000，当前段落6,000。全文不自动截断，具体模型仍须支持输入上下文。
- 支持本人配置的文本渠道和精确 Muse 文本 ID：`muse-spark`、`muse-service-spark`；后者通过服务器加密账号池租约调用。文本调用超时90秒、响应最多2MiB，不自动重试。
- 模型结果兼容纯JSON对象、单个JSON/无语言代码围栏，或前后有说明但只有一个完整对象的回复。解析器限制120,000字符与128层嵌套，理解字符串内括号/引号转义；拒绝截断、数组根、多对象、多围栏、未知围栏语言与重复字段，不补括号、不猜测结构。解析成功后仍走原有档案/五镜头校验。
- Muse 网关当前限制组合后的用户上下文最多120,000字符，接近全文上限时须按章节输入；UI不会声称模型已读到被截断的原文。
- 抽档记录角色所有别名、固定核心形象、衣着、性格、音色及原文未说明的拟定项。锁定核心不可被后续模型改写；用户必须先显式解锁。历史镜头仍引用的档案不得删除。
- 角色全身/三视图、无人实景和白底完整道具提示词由服务端生成。尚未调用图像模型时只是提示词。
- 每段严格五镜头，时间为0–3、3–6、6–9、9–12、12–15秒，每镜3秒。台词角色必须出镜，引用档案必须存在。
- 后续段落模型输入包含全剧设定、当前段落、档案、最近三段剧本/分镜和上一段末镜状态。第一镜场景ID必须接续上一段末镜；方位、服饰、光线、天气和动作的自然延续由提示词约束，仍需人工预览确认。
- 每段保存原始剧本、精确输出文本、五个镜头和当时的档案快照，手动改档不会反向改变历史段落导入结果。
- 固定真人写实、无字幕、音效、无音乐、无旁白；纯TXT导出只含指定风格前缀、出镜角色汇总和五行分镜。

## 持久化、取消和故障

任务写入MySQL `canvas_story_task`；画布剧本快照写入 `project_canvas_story`。取消和发布在任务状态/租约边界判定，已取消任务不能覆写快照。请求已经发往供应商时，取消不能承诺退还上游额度。

运行租约300秒；执行进程中断或租约过期后任务标为 failed，保留原快照，不自动重发可能已经计费的模型请求。用户可明确重新提交。任务成功后重复执行不会再次请求模型。

快照上限2MiB，每个画布最多100段；可导出后拆分至新画布。V14建立表结构，项目删除时级联移除其工作流。

## Host UI 与画布应用

`CanvasStoryWorkflow` props：`open, onOpenChange, projectId, modelCatalogVersion?, onSettings?, onApply`，按用户ID及项目ID设置 React `key`。

`onApply(StoryApplyPayload)` 提供本段脚本/纯分镜、五个镜头的图像/视频提示词以及实际引用的角色/场景/道具。画布端建立连线节点并展示执行入口；应用不自动发起付费生图或视频请求。

分镜的15秒是导演时间规划，实际视频模型须按其可用时长执行；不能把不支持3秒的供应商调用伪装成五段3秒成片。
