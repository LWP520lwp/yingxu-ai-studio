# 多模态画布生成

使用新平台的 `/api` 接口完成生成与画布操作。上游 Muse 仅是可替换的模型供应商；不要把其生成能力描述为团队自研模型。第一版提供图片、视频任务，剧本到完整多镜头成片仍是组合规划。

调用前阅读 [平台 API 与操作约定](references/platform-api.md)。在实施状态、字段或路由与该参考不一致时，以仓库 `apps/api/API_CONTRACT.md` 和当前服务响应为准，纠正过时假设。

## 选择流程

- 文生图：读取 [image-create](recipes/image-create.json)，使用 `kind: image`。
- 已有图片转视频：读取 [image-to-video](recipes/image-to-video.json)，使用 `kind: video`，引用本平台图片资产 ID。
- 剧本或分镜到视频：读取 [storyboard-to-video](recipes/storyboard-to-video.json)。它是规划配方，不能把多镜头生成、自动拼接、配音和字幕宣称为已经实现的单一能力。

## 执行约定

1. 先读取 `/api/bootstrap`，确认会话、集成状态和实际暴露的模型能力。模型出现在列表中不等于真实生成已验收；没有对应能力时清楚说明。
2. 通过平台登录建立会话。创建任务、上传、取消和保存项目均使用该会话；生产环境使用正式认证。不要把开发专用 `/api/auth/local` 当生产登录方式，也不要假定公网端点无鉴权。
3. 获取项目当前文档和 `revision`，确定目标 `nodeId`。新节点先通过正常项目保存持久化；引用素材先上传为本平台资产。节点和资产属于当前项目／用户，不传外部文件路径。
4. 根据用户已授权的生成类型、数量和素材创建任务，每次新的逻辑提交使用唯一 `Idempotency-Key`，对同一请求的传输重试保留相同键。只调查状态或配置时不发生成请求。
5. 保留任务 ID，订阅 `/api/events` 或有界轮询 `/api/jobs/{id}`。重连后从持久任务查询对账。等待超时可报告“仍处理中”和任务 ID；不把等待超时等同于上游失败，也不另建重复任务。
6. 成功后读取 `resultAssetId`／`resultUrl`，呈现为目标节点候选版本。按用户的应用意图获取最新项目，再以当前 `baseRevision` 保存；保留旧版本。若生成期间节点或内容已变，保留候选并说明对应输入，不覆盖新的编辑。
7. 记录模型、输入修订号、引用素材与最终任务状态。失败报告实际错误；`unknown_external` 保留待核实状态，不能自动重发可能已消费的生成。

## 边界

生成密钥、上游 Cookie 和账号资料只在后端。skill、浏览器、画布 JSON、recipe 和日志均不携带这些值；不读取或输出旧 Muse 部署的 `.env`。本 skill 不负责账号登录自动化、密钥提取或上游管理接口。

取消已提交任务只保证平台尽力停止后续处理；除非服务响应明确确认，不声称上游已经停止生成或不会计费。
